# Снижение галлюцинаций в русскоязычных юридических RAG-системах: систематическое сравнение гибридного, графового и агентного поиска

Эксперименты по сравнению RAG-стратегий (naive → hybrid → graph) на русскоязычном трудовом праве РФ. Реализованы `zero_shot` и `naive_rag`; ответы можно оценивать автоматически LLM-судьёй с флагом `--evaluate`.

## Установка

```bash
py -3.10 -m venv venv
venv\Scripts\python -m pip install --extra-index-url https://download.pytorch.org/whl/cpu -r requirements-lock.txt
```

Версия Python зафиксирована в `.python-version`. `requirements-lock.txt` фиксирует версии текущего окружения; см. ограничение о хешах и способе установки CPU-версии PyTorch внутри файла.

Ключи API — в `.env` (шаблон — `.env.example`).

## Запуск

```bash
venv\Scripts\python run.py --mode zero_shot --model gigachat
venv\Scripts\python run.py --mode zero_shot --model deepseek
venv\Scripts\python run.py --mode naive_rag --model gigachat
venv\Scripts\python run.py --mode zero_shot --model deepseek --evaluate
```

* `--limit N` — обработать только первые N вопросов (для проверки)
* `--output-path PATH` — свой путь к результату (внутри `data/` запрещён)
* `--force` — очистить ответы и перегенерировать всё заново
* `--evaluate` — оценить сгенерированные ответы по эталону; `--evaluate-model` задаёт алиас модели-судьи (по умолчанию `deepseek`)

Повторный запуск продолжает таблицу по стабильному ID `№`: готовые ответы пропускаются, незаполненные запрашиваются заново. Продолжение разрешается только при совпадении датасета, корпуса и условий прогона; старые результаты без необходимых метаданных требуют нового файла или `--force`. Быстрый тест:

```bash
venv\Scripts\python run.py --mode zero_shot --model gigachat --limit 5 --output-path results\_test\test.xlsx
```

### Условия и `--force`

Рядом с таблицей лежит `*_metadata.json` с условиями прогона, хешами входных данных, состоянием запуска и provenance каждого ответа (фактическая модель, fingerprint/usage, а для RAG — найденные фрагменты). XLSX сохраняется после каждого ответа атомарно. При ошибке или прерывании статус отражается в метаданных; при расхождении условий скрипт прекращает продолжение до API-запросов.

`--force` снимает проверку и генерирует ответы с нуля: очищает колонку ответов и разметку, остальные колонки не трогает. Бэкапа нет, поэтому применяйте осознанно. Изменение git-коммита отмечается предупреждением; хеши датасета и корпуса входят в проверяемые условия.

### Ограничение воспроизводимости

Модели вызываются через внешние API. Даже при совпадении Git-коммита, промпта, температуры и входных данных провайдер может изменить модель или внутреннюю конфигурацию, поэтому повторный API-запрос не гарантированно вернёт тот же ответ. Для анализа конкретного прогона следует использовать сохранённые XLSX, metadata и provenance; подробное ограничение описано в [ADR-0001](docs/decisions/ADR-0001-experiment-reproducibility.md).

### Отдельная оценка готового файла

Чтобы оценить уже сохранённые ответы отдельно от генерации:

```bash
venv\Scripts\python evaluate.py --model deepseek --file_path results\zero_shot\deepseek\zero_shot_deepseek_v2.xlsx
```

`--model` принимает алиасы `gigachat` или `deepseek`; `--force` перезапускает уже заполненные оценки. Скрипт определяет колонку ответа по метаданным рядом с XLSX и сохраняет оценки после каждой строки, используя общий слой моделей `llm`.

## Наивный RAG

Векторный поиск по корпусу ТК РФ без реранкера: `multilingual-e5-small` (HuggingFace, веса закреплены ревизией) + Chroma с косинусом. Корпус чанкуется по строкам до 900 символов с перекрытием 150; в каждый чанк добавлен заголовок статьи. Поиск берёт до `3 × top_k` кандидатов (сейчас 15), затем дедуплицирует их по статье и передаёт до пяти разных статей.

Индекс собирается автоматически при первом запуске `naive_rag` и лежит в `data/index/naive_rag_e5small_v1/`. При изменении корпуса, параметров или кода индексирования его fingerprint перестаёт совпадать, и индекс пересобирается. Настройки — в `config.py`.

Модель отвечает только по найденным фрагментам и ссылается на них `[1]`, `[2]`; при нехватке норм в контексте обязана ответить, что ответа в фрагментах нет. Рядом с таблицей результатов ложится `*_retrieval.jsonl` с полными текстами фрагментов и счетами — по нему считается recall@k. Колонка «Найденные статьи_*» — номера статей со счетами, для оценки поиска без чтения JSONL.

## Ошибки и повторы

До 5 попыток на запрос: паузы 2, 4, 8, 16 с (или `Retry-After` от сервера), таймаут запроса 30 с. Повторяются только временные сбои (сеть, таймауты, 408, 429, 5xx), остальные завершают прогон сразу. Логи — в `logs/{mode}_{model}_{дата}.log`. Если попытки исчерпаны, скрипт выходит с кодом 1; полученные ответы уже сохранены и при перезапуске будут пропущены.

## Модели

Реестр — `MODELS` в `config.py`: алиас CLI → провайдер, имя модели в API (`api_model`) и подпись для колонки (`label`). Новый провайдер добавляется билдером в `llm/factory.py`.

`llm.create_llm(alias)` — обёртка с нашими повторами и метаданными (`response_model`, `usage`, `system_fingerprint`); её используют эксперименты. `llm.create_chat_model(alias)` — «сырой» LangChain-клиент для цепочек и агентов.

## Решения и ограничения

Краткие обоснования ключевых решений и их статус собраны в [ADR-0001](docs/decisions/ADR-0001-experiment-reproducibility.md). В частности, выборка 15 кандидатов перед дедупликацией до пяти статей — текущая эвристика; её оптимальность должна проверяться отдельным экспериментом.

## Структура

* `config.py` — пути, ключи, реестр моделей `MODELS`, параметры повторов
* `llm/` — общий слой: создание клиентов, повторы, разбор ответа
* `prompts.py` — промпты и `PROMPT_VERSION`
* `run.py` — единый раннер экспериментов
* `experiments/zero_shot/` — `pipeline.py`; новый режим регистрируется через `@register_pipeline("имя")`
* `experiments/naive_rag/` — `index.py` (чанкинг и Chroma), `prompts.py`, `pipeline.py`
* `data/dataset.xlsx` — 211 кейсов с эталонными ответами и статьями ТК РФ
* `data/corpus/tk_rf_articles.jsonl` — корпус статей ТК РФ (534 статьи)
* `data/index/` — индекс RAG (не хранится в git)

## Результаты

`results/{mode}/{model}/{mode}_{model}_{версия_промпта}.xlsx`, рядом — метаданные прогона.

При `--evaluate` заполняются колонки «Была галлюцинация (да/нет)» и «Комментарий»; сведения о модели-судье и промпте оценки сохраняются в метаданных.
