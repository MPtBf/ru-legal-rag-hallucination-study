# ADR-0003: Перегенерация RAG-ответов на промпте v3

**Дата:** 07.11.2026
**Статус:** принято (решение участника проекта).

## Контекст

По [ADR-0002](ADR-0002-zero-shot-prompt-v1.md) zero-shot промпт возвращён к v1, а из RAG-надстройки удалён номер `6.`, продолжавший нумерованный список, которого больше нет в `SYSTEM_PROMPT`. Содержание RAG-инструкций при этом не менялось.

Сохранённые RAG-результаты `*_v2.xlsx` получены с прежним текстом `RAG_SYSTEM_PROMPT` (с номером `6.`) и полностью заполнены: 211/211 ответов и 211/211 строк автоматической оценки. `run.py` сохраняет полный `system_prompt` в metadata и не продолжает файл при несовпадении условий, поэтому перегенерация в те же v2-файлы потребовала бы `--force` и перезаписи старых xlsx, metadata и retrieval.

Принято решение перегенерировать RAG-ответы (кроме zero-shot) и сохранить прежние v2-результаты без изменений.

## Решение

1. `RAG_PROMPT_VERSION` поднимается до `v3`, чтобы версия отражала фактический текст промпта.
2. Перегенерируются все четыре RAG-запуска: `naive_rag` и `hybrid_rag` для GigaChat и DeepSeek.
3. Новые файлы пишутся по обычной схеме `results/{mode}/{model}/{mode}_{model}_v3.xlsx`; рядом сохраняются `*_v3_metadata.json` и `*_v3_retrieval.jsonl`.
4. Прогоны выполняются с `--evaluate`: автоматическая разметка DeepSeek перегенерируется вместе с ответами.
5. Старые `*_v2.xlsx`, metadata и retrieval не изменяются; zero-shot не перегенерируется.
6. Результаты каждого прогона коммитятся отдельно, чтобы metadata следующих запусков фиксировала `git_dirty=false`.

## Обоснование

- Промпт изменился, поэтому оставлять версию `v2` значило бы смешивать разные условия генерации под одной меткой.
- Новые файлы позволяют сохранить прежние результаты и сравнивать прогоны, не перезаписывая историю.
- Отдельные коммиты результатов уменьшают риск потерять уже полученные ответы и делают состояние кода на момент каждого запуска воспроизводимым.

## Последствия и ограничения

- Результаты v3 не являются побитовым повтором v2: изменился текст промпта, а внешние модели могли обновиться. Сравнение v2 и v3 следует описывать как разные условия, а не как повторный запуск того же эксперимента.
- Автоматическая разметка DeepSeek не является человеческой разметкой и не заменяет ручную проверку.
- При сбое API прогон останавливается; повторный запуск той же команды продолжает с места остановки.
- Решение ADR-0002 в части `RAG_PROMPT_VERSION` заменено этим ADR; откат zero-shot до v1 остаётся в силе.

## Фактические результаты

Заполняется после завершения прогонов: даты, длительности, пути файлов и замеченные отклонения.
